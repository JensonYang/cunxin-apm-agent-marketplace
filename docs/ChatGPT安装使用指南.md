# 寸心 APM 客诉与行为分析助手：ChatGPT 安装与使用指南

本文面向需要在 ChatGPT 中使用 `cunxin-apm-support-agent` 的同事，以及负责统一部署的 ChatGPT 工作空间管理员。

## 适用范围

该插件用于辅助分析“寸心来印”生产客诉、客户行为、打印链路日志和禅道 Bug。它会在需要时关联本机的 `cn-saas-printer` `origin/dev` 代码进行判断。

- 建议使用 ChatGPT 桌面版；涉及本地脚本、开发代码或禅道 MCP 时尤其如此。
- 是否可安装或使用插件，取决于你的 ChatGPT 计划、工作空间、角色和管理员策略。
- 插件只读查询 APM；请仅在业务授权范围内输入生产用户 ID、打印 ID 和禅道链接。

## 个人安装（推荐）

### 1. 前置条件

- 已登录可以使用插件的 ChatGPT 账号或公司工作空间。
- 本机已安装并可使用 Codex 命令行。
- 能访问 GitHub。

### 2. 添加插件市场

打开终端，执行：

```bash
codex plugin marketplace add https://github.com/JensonYang/cunxin-apm-agent-marketplace.git --sparse .agents/plugins
```

命令完成后，重启 ChatGPT 桌面版，使本地插件市场重新加载。

### 3. 安装插件

1. 在 ChatGPT 左侧边栏打开“插件”。
2. 在“个人”或“你的工作空间”中搜索 `cunxin-apm-support-agent`。
3. 打开插件详情，确认其用途和权限后选择“安装”。
4. 新建一个聊天，直接描述待排查的问题即可；相关场景下 ChatGPT 会自动使用该插件。

> 如果插件详情显示“仅桌面版”，请改用 ChatGPT 桌面版。浏览器版不能替代需要本地脚本或本地 MCP 的能力。

## 工作空间统一部署（管理员）

适用于希望让多个同事在同一个 ChatGPT Business、Enterprise 或 Edu 工作空间内安装的场景。

1. 切换到目标 ChatGPT 工作空间，打开“管理控制台” > “插件”。
2. 选择“添加” > “导入市场”。
3. 按下列内容填写：

   | 字段 | 填写内容 |
   | --- | --- |
   | Source | `https://github.com/JensonYang/cunxin-apm-agent-marketplace` |
   | Path | 留空（市场清单位于仓库根目录的 `.agents/plugins/marketplace.json`） |
   | Branch | `main`，或按发布流程填写已审核的标签/提交 |

4. 选择“导入市场”，按界面提示授权 GitHub 读取该公开仓库。
5. 打开已导入的 `cunxin-apm-support-agent`，设置安装策略：
   - “可用”：同事可自行在插件目录安装。
   - “已安装”：为符合条件的成员或角色自动安装。
6. 先选择一名有生产排查授权的同事完成试用，再扩大范围。

市场会自动同步 GitHub 更新；管理员也可以在“插件” > “市场”中手动选择“立即同步”。GitHub 仓库中的安装策略字段不会覆盖工作空间中的管理员设置，因此管理员需要在 ChatGPT 中单独确认安装策略和相关访问控制。

## 首次使用前的可选准备

### 需要结合客户端代码时

如果要将日志与客户端实现一起分析，请在本机按照公司内部开发规范准备 `cn-saas-printer` 和其 `scripts` 子项目，并确保可以读取两个仓库的 `origin/dev`。插件不会切换、重置或清理你的工作分支。

### 需要通过禅道 Bug 联动分析时

直接发送禅道 Bug 链接即可。智能体会先检查当前用户是否已注册 `zentao-bug-report` MCP；未安装时自动用 `npm exec` 从 `https://nexus.znoinc.com/repository/npm/` 安装并注册 `zentao-debug`，不会从 npmjs 安装，也不会修改客户端项目依赖或全局 npm 目录。首次安装需要访问 Nexus 和禅道 MCP 服务，完成后请重新打开聊天并重新发送同一链接。

MCP 服务端负责禅道认证；不要在聊天、终端命令、仓库地址或文档中填写禅道密码。

## 常用提问模板

在新聊天中尽量提供明确的对象和时间范围，以减少无关日志查询。

### 生产客诉排查

```text
请分析用户 1773074 在 2026-10-12 的寸心来印日志。
客户反馈：列表有数据但界面卡顿、不渲染。
请给出：已证实的日志事实、可能原因、关联的代码位置和下一步验证建议。
```

### 打印链路分析

```text
请分析打印 ID <打印ID> 在 <日期> 的完整链路。
重点检查：任务是否创建、脚本是否执行、是否存在前端错误、接口超时或重试。
```

### 禅道 Bug 联动

```text
请根据这个禅道 Bug 链接分析问题：<禅道链接>。
如 Bug 内容明确包含用户 ID、打印 ID 和日期，请结合当天 APM 日志及 cn-saas-printer 的 origin/dev 代码给出结论。
```

### 客户行为统计

```text
请统计用户 <用户ID> 在 <开始日期> 到 <结束日期> 的使用行为：
登录、配置变更、进入打印、创建任务、成功/失败和异常信号。
请输出脱敏的中文摘要，不要展示原始日志载荷。
```

## 输出如何理解

报告会区分以下内容：

- “日志已证实”：可直接从 APM 事件或接口结果确认的事实。
- “代码上可能发生”：根据 `origin/dev` 实现推断、但尚需复现或补充证据验证的路径。
- “下一步建议”：建议补充的时间窗口、用户/打印标识、前端日志或配置截图。

“打印流程完成”通常表示任务已提交到本地打印链路，不等同于物理成片颜色、纸张或驱动结果完全正确；涉及驱动、设备或色彩配置时，仍需结合现场配置确认。

## 安全要求

- 不要在 ChatGPT、GitHub Issue、截图或文档中粘贴账号密码、访问令牌、完整原始日志、会话 ID、IP、图片 URL 或客户隐私数据。
- 使用真实生产数据前，请确认自己具备对应的业务授权。
- 当前插件市场仓库为公开仓库：任何人可查看和下载仓库内容，但不能直接修改原仓库；只有仓库所有者和具有写权限的协作者能够推送修改。
- 公开仓库中的内容会被互联网访问。管理员应在每次发布前检查是否意外包含内部地址、凭据、客户数据或其他不应公开的信息。

## 常见问题

### 找不到插件

确认已执行添加市场命令并重启 ChatGPT 桌面版；再检查 ChatGPT 工作空间是否允许你使用插件。若是工作空间统一部署，请联系管理员确认插件是否已设为“可用”或“已安装”。

### 无法分析禅道链接

首次发送链接时，智能体会尝试自动初始化禅道 MCP；初始化完成后必须重新打开聊天并再次发送链接。若自动安装失败，请确认本机可使用 `npm`、能访问 `https://nexus.znoinc.com/repository/npm/` 和禅道 MCP 服务，再让智能体重试。若 Bug 未提供用户 ID、打印 ID 或明确日期，插件不会盲目扫描大量历史生产日志；请补充这些信息。

### 报告没有关联代码

确认本机已准备 `cn-saas-printer` 和 `scripts`，并且本地 Git 能读取其 `origin/dev`。插件不会自动索取或保存 Git 凭据。

### 更新后没有生效

个人安装请重启 ChatGPT 桌面版；工作空间统一部署请让管理员在“市场”中选择“立即同步”，并查看同步结果。
